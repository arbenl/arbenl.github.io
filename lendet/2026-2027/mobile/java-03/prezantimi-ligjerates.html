LIGJËRATA 3 · 05 / 14

Si e lexon Next.js këtë rrjedhë?

src/app/page.tsx                       → /
src/app/udhetimi/[id]/page.tsx         → /udhetimi/1
src/app/udhetimi/[id]/kerkesa/page.tsx → /udhetimi/1/kerkesa

App Router i Next.js i lidh dosjet me adresat. E njëjta dosje [id] hap udhëtimin 1, 2 ose 3; nuk krijojmë një skedar të ri për secilin.

LIGJËRATA 3 · 07 / 14

Një burim për tri karta

const udhetimet = [
  { id: "1", nisja: "Prishtinë", ora: "08:00", vende: 2 },
  { id: "2", nisja: "Fushë Kosovë", ora: "08:15", vende: 1 },
  { id: "3", nisja: "Lipjan", ora: "07:45", vende: 0 }
];

Pse vetëm një listë? Karta dhe faqja e detajeve lexojnë të njëjtin udhëtim. Kështu ora e kartës nuk kundërshton orën te detajet.

Fillojmë me të dhëna fiktive. Në Javën 4 do t’i lexojmë nga baza e të dhënave.

LIGJËRATA 3 · 08 / 14

Lidhja duhet ta ruajë zgjedhjen

Karta me id: "2"→Prek “Shiko detajet”→URL /udhetimi/2
<Link href={`/udhetimi/${udhetim.id}`}>
  Shiko detajet
</Link>

Numri në adresë nuk është zbukurim: ai i tregon faqes cilat të dhëna të lexojë.

LIGJËRATA 3 · 09 / 14

Si gjendet udhëtimi i zgjedhur?

URL /udhetimi/2→id = "2"→Gjej udhëtimin 2
const { id } = await params;
const udhetim = udhetimet.find((u) => u.id === id);

Faqja e detajeve lexon id nga adresa. Në versionet aktuale të Next.js, params pritet me await.

LIGJËRATA 3 · 11 / 14

“Në pritje” është simulim, jo rezervim

⏳ Sot: shfaqim ekranin

Klikimi hap tekstin “Simulim: Në pritje”. Nuk ruhet kërkesë dhe shoferi nuk merr njoftim.

🔔 Më vonë: veprim real

Kërkesa do të ruhet, shoferi do të përgjigjet dhe statusi do të përditësohet. Këto hapa nuk kërkohen në Javën 3.

Nëse udhëtimi ka zero vende, butoni “Kërko vend” nuk duhet të ofrohet.
