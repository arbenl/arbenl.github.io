Hyrja me GitHub dhe ndryshimi me leje

Sot shton një veprim të vogël dhe të provueshëm: shoferi ndryshon orën e udhëtimit të vet. Përdor të njëjtin projekt dhe Neon nga Java 4.

Puno në çift për ndihmë, por secili ruan aplikacionin, OAuth App dhe databazën e vet. Mos ndani sekrete. Skano QR (Quick Response – përgjigje e shpejtë) kur e shfaq profesori; dorëzimi i detyrës bëhet veçmas.

Harta e ushtrimeve

Provoje aplikacionin lokalisht, pastaj ruaj dhe dorëzo punën. Hyrja me GitHub dhe dorëzimi në GitHub janë dy veprime të ndryshme.

Dy rezultate për t’i provuar: ID 2 ruhet në 08:25; ID 1 refuzohet dhe mbetet 08:00. Pastaj bën Commit → Push → dorëzim dhe lexon kontrollin automatik.

2. Lidh hyrjen · 10–25 min

2.1 · Krijo OAuth App në GitHub

Ku: GitHub → fotografia e profilit → Settings → Developer settings → OAuth Apps → New OAuth App. OAuth (Open Authorization – autorizim i hapur) përdoret këtu për hyrjen me profilin GitHub.

Kliko Register application, kopjo Client ID, pastaj Generate a new client secret. Client ID nuk është emaili, username ose ID-ja jote e studentit.

2.2 · Instalo bibliotekën në projekt

Nga GitHub kthehu te VS Code. Ndal serverin me Ctrl+C në terminal. Sigurohu që je në dosjen ku ndodhet package.json.

Çfarë bën ky kod? Komanda instalon bibliotekën NextAuth që trajton hyrjen dhe daljen me GitHub. Ekzekutoje në terminal; nuk krijon skedar për këtë komandë.

npm install next-auth@4.24.15

Prit të përfundojë instalimi. Përdorim versionin e njëjtë në të gjithë shembujt; mos përziej udhëzime për v5 ose next-auth@beta.

2.3 · Gjenero sekretin e sesionit

Çfarë bën ky kod? Kjo komandë krijon një vlerë të rastësishme private për mbrojtjen e sesionit. Ekzekutoje në të njëjtin terminal dhe kopjo vetëm rezultatin, pa e publikuar. Rezultati përdoret në rreshtin NEXTAUTH_SECRET të hapit 2.4.

node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"

2.4 · Lidhi vlerat në .env.local

Në VS Code hap .env.local pranë package.json. Nëse kodi është në aplikacioni/, edhe ky skedar është brenda asaj dosjeje.

Çfarë bën ky kod? Këta rreshta i tregojnë aplikacionit cilin OAuth App të përdorë, sekretin e sesionit dhe adresën lokale. GITHUB_ID dhe GITHUB_SECRET vijnë nga 2.1; NEXTAUTH_SECRET nga 2.3. Zëvendëso tekstin brenda thonjëzave me vlerat e tua. Mbaje rreshtin ekzistues DATABASE_URL të Javës 4.

GITHUB_ID="CLIENT_ID_I_OAUTH_APP"
GITHUB_SECRET="CLIENT_SECRET_I_OAUTH_APP"
NEXTAUTH_SECRET="VLERA_E_GJENERUAR_NGA_KOMANDA"
NEXTAUTH_URL="http://localhost:3000"

Kontrollo portin: shembulli përdor 3000. Nëse terminali përdor 3001, ndrysho Homepage, callback dhe NEXTAUTH_URL në 3001, ose mbyll procesin që zë portin 3000. localhost dhe 127.0.0.1 nuk duhen përzier në konfigurim.

Kontrollo .gitignore: rreshti .env* mbetet. Mos kopjo sekretet në kod, raport, pamje ose Issue. Rinis serverin pas çdo ndryshimi të variablave.

Para se të vazhdosh: Instalimi ka përfunduar, .env.local është ruajtur dhe adresat/porti përputhen me OAuth App në GitHub.

Hapi 3 · SQL

SQL · rolet dhe pronari

Skedari: schema-java05.sql

Ekzekuto në Neon SQL Editor para hyrjes. Pastaj ruaje këtë skedar pranë package.json.

Të dhënat që i nevojiten hyrjes

Çfarë bën ky kod? Krijon tabelën profilet, ku ruhet identiteti dhe roli. Profili i ri merr automatikisht rolin udhetar. Shton shofer_id te udhëtimet për të treguar pronarin. ID 1 lidhet me një shofer fiktiv që më vonë ta provojmë refuzimin; ID 2 ia caktojmë llogarisë sate në hapin 4. Komanda e fundit shfaq udhëtimet për kontroll.

-- Ekzekuto vetëm në databazën tënde të laboratorit nga Java 4.
CREATE TABLE IF NOT EXISTS profilet (
  github_id TEXT PRIMARY KEY,
  emri TEXT NOT NULL,
  roli TEXT NOT NULL DEFAULT 'udhetar' CHECK (roli IN ('udhetar', 'shofer'))
);
ALTER TABLE udhetimet ADD COLUMN IF NOT EXISTS shofer_id TEXT REFERENCES profilet(github_id);
-- Pronari fiktiv i ID 1: nuk është llogari reale dhe nuk përdoret për hyrje.
INSERT INTO profilet (github_id, emri, roli)
VALUES ('DEMO-SHOFER-2', 'Shoferi tjetër (demo)', 'shofer')
ON CONFLICT (github_id) DO NOTHING;
UPDATE udhetimet SET shofer_id = 'DEMO-SHOFER-2'
WHERE id = '1' AND shofer_id IS NULL;
SELECT id, ora, shofer_id FROM udhetimet ORDER BY id;

Hapi 3 · A

A · identiteti dhe sesioni

Skedari: src/lib/auth.ts

Krijo këtë skedar. GitHub verifikon llogarinë; ID-ja e sesionit vjen nga biblioteka, jo nga formulari.

Si e njeh aplikacioni përdoruesin?

Çfarë bën ky kod? Lexon vlerat private të hapit 2 dhe konfiguron hyrjen me GitHub. Pas hyrjes, sesioni mban ID-në e përdoruesit të verifikuar, që serveri ta njohë edhe në kërkesat e tjera. Sesioni zgjat deri në dy orë. Roli nuk merret nga GitHub: atë e lexojmë nga Neon te D.

import "server-only";
import type { DefaultSession, NextAuthOptions } from "next-auth";
import GitHubProvider from "next-auth/providers/github";

// GitHub verifikon identitetin. Rolin e lexojmë veçmas nga Neon.
export const authOptions: NextAuthOptions = {
  secret: process.env.NEXTAUTH_SECRET,
  providers: [GitHubProvider({
    clientId: process.env.GITHUB_ID ?? "",
    clientSecret: process.env.GITHUB_SECRET ?? "",
  })],
  session: { strategy: "jwt", maxAge: 2 * 60 * 60 },
  callbacks: {
    async session({ session, token }) {
      if (session.user && token.sub) session.user.id = token.sub;
      return session;
    },
  },
};

declare module "next-auth" {
  interface Session {
    user: { id: string } & DefaultSession["user"];
  }
}

Para se të vazhdosh: auth.ts është ruajtur brenda src/lib/; vlerat private mbeten vetëm në .env.local.

Hapi 3 · D

D · kontrolli në server

Skedari: src/lib/lejet.ts

Krijo helper-in. profiliIm lexon sesionin dhe Neon. ndryshoOren kontrollon rolin, fushat dhe pronarin.

Kush lejohet ta ndryshojë orën?

Çfarë bën ky kod? profiliIm() lexon identitetin nga sesioni dhe profilin nga Neon; në hyrjen e parë krijon një udhëtar. ndryshoOren() kontrollon hyrjen, rolin shofer, ID-në dhe formatin e orës. UPDATE ruan ndryshimin vetëm kur udhëtimi i përket këtij përdoruesi dhe roli në databazë është ende shofer. Kthen një rezultat si ruajtur ose ndaluar.

import "server-only";
import { getServerSession } from "next-auth";
import { authOptions } from "./auth";
import { getSql } from "./db";

type Profil = { id: string; emri: string; roli: "udhetar" | "shofer" };

export async function profiliIm(): Promise<Profil | null> {
  const session = await getServerSession(authOptions);
  const id = session?.user?.id;
  if (!id || !/^\d+$/.test(id)) return null;
  const sql = getSql();
  // Çdo hyrje e re fillon si udhëtar. Formulari nuk mund të zgjedhë rol.
  await sql`INSERT INTO profilet (github_id, emri) VALUES (${id}, ${session.user.name ?? "Student"})
    ON CONFLICT (github_id) DO NOTHING`;
  const rows = await sql`SELECT github_id AS id, emri, roli FROM profilet WHERE github_id = ${id}`;
  return rows[0] as Profil;
}

export async function ndryshoOren(id: string, ora: string) {
  const p = await profiliIm();
  if (!p) return "hyr";
  if (p.roli !== "shofer") return "ndaluar";
  if (!/^[123]$/.test(id) || !/^([01][0-9]|2[0-3]):[0-5][0-9]$/.test(ora)) return "fushe";
  const sql = getSql();
  // Pronari vjen nga sesioni; jo nga një fushë e formularit.
  const rows = await sql`UPDATE udhetimet SET ora = ${ora}
    WHERE id = ${id} AND shofer_id = ${p.id}
      AND EXISTS (SELECT 1 FROM profilet WHERE github_id = ${p.id} AND roli = 'shofer')
    RETURNING id`;
  return rows.length === 1 ? "ruajtur" : "ndaluar";
}

Hapi 3 · E

E · veprimi i ruajtjes

Skedari: src/app/panel/actions.ts

Krijo skedarin. use server e ekzekuton veprimin në server. Leja kontrollohet brenda funksionit, jo vetëm kur faqja hapet.

Si shkon formulari deri te databaza?

Çfarë bën ky kod? Lexon ID-në dhe orën nga formulari dhe thërret ndryshoOren() të D-së. Nëse ruhet, kërkon rifreskimin e listës dhe detajeve të ID 2. Pastaj e kthen përdoruesin te paneli me rezultatin në adresë. "use server" e mban këtë veprim në server; leja kontrollohet në çdo ruajtje.

"use server";
import { redirect } from "next/navigation";
import { revalidatePath } from "next/cache";
import { ndryshoOren } from "@/lib/lejet";

export async function ruajOren(formData: FormData) {
  let mesazh: string;
  try {
    mesazh = await ndryshoOren(String(formData.get("id") ?? ""), String(formData.get("ora") ?? ""));
  } catch {
    mesazh = "databaza";
  }
  if (mesazh === "ruajtur") {
    revalidatePath("/");
    revalidatePath("/udhetimi/2");
  }
  // redirect qëndron jashtë try/catch: Next.js e përdor si kontroll rrjedhe.
  redirect("/panel?m=" + mesazh);
}

Çfarë sheh përdoruesi në ekran?

Çfarë bën ky kod? Bashkon butonat e C-së, profilin e D-së dhe veprimin e E-së. Pa hyrje shfaq butonin Hyr; udhëtarit i shfaq emrin dhe rolin; shoferit i shton formularin për ID 2. export const dynamic = "force-dynamic";
const mesazhet: Record<string, string> = {
  hyr: "Hyr në llogari para se të ndryshosh udhëtimin.",

4. Hyr dhe cakto pronarin · 45–55 min

  1. Nis npm run dev dhe hap http://localhost:3000/panel, ose Hyr / Paneli im nga lista.
  2. Kliko Hyr me GitHub. Në faqen GitHub prano hyrjen në OAuth App tënd. Pas kthimit duhet të shfaqet emri dhe roli udhetar.
  3. Kopjo numrin pas ID ime GitHub në panel. Në dy komandat e mëposhtme zëvendëso SHENO_ID_TENDE me këtë numër. Mbaji thonjëzat.
  4. Ekzekuto në Neon SQL Editor dhe rifresko panelin. Duhet të shfaqet roli shofer dhe formulari për ID 2.

Çfarë bën ky kod? Rreshti i parë e bën profilin tënd shofer. I dyti të cakton pronar vetëm të udhëtimit ID 2; ID 1 mbetet e shoferit tjetër. I treti shfaq udhëtimet që të verifikosh pronarin. Në të dy vendet SHENO_ID_TENDE shkruaj të njëjtin numër nga paneli dhe ekzekutoji në Neon, jo në terminal.

UPDATE profilet SET roli = 'shofer' WHERE github_id = 'SHENO_ID_TENDE';
UPDATE udhetimet SET shofer_id = 'SHENO_ID_TENDE' WHERE id = '2';
SELECT id, ora, shofer_id FROM udhetimet ORDER BY id;

Pse nga SQL Editor? Në laborator ti je administratori i databazës tënde fiktive. Në aplikacionin real përdoruesi nuk zgjedh vetë rol ose pronar. Nuk ndryshojmë rolin nga një input, URL ose buton në shfletues.

Para se të vazhdosh: Pas hyrjes shfaqen emri dhe ID-ja jote. Pas komandave SQL dhe rifreskimit, paneli tregon shofer dhe formularin për ID 2.
