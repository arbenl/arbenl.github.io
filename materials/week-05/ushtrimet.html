1. Përgatitu · 0–10 min

  1. Hap repository-n ekzistues në GitHub Desktop → Open in Visual Studio Code.
  2. Në terminal: cd aplikacioni nëse kodi është aty; npm run dev.
  3. Kontrollo tri kartat dhe detajet që lexojnë nga Neon. Nëse Java 4 nuk punon, rikthe pikën e nisjes dhe kërko ndihmë menjëherë.
  4. Shkarko java-05.md pranë README, jashtë aplikacioni/.

Shembujt përdorin src/. Nëse ke app/ pa src/, hiq vetëm prefiksin src/ nga rrugët e skedarëve. Nëse package.json është pranë README, puno aty.

2. Lidh hyrjen · 10–25 min

Ku: GitHub → fotografia e profilit → Settings → Developer settings → OAuth Apps → New OAuth App. OAuth (Open Authorization – autorizim i hapur) përdoret këtu për hyrjen me profilin GitHub.

Shto këto rreshta në .env.local pranë package.json. Zëvendëso tekstin brenda thonjëzave me vlerat e tua. DATABASE_URL e Javës 4 mbetet aty.

Kontrollo portin: shembulli përdor 3000. Nëse terminali përdor 3001, ndrysho Homepage, callback dhe NEXTAUTH_URL në 3001, ose mbyll procesin që zë portin 3000. localhost dhe 127.0.0.1 nuk duhen përzier në konfigurim.

Kontrollo .gitignore: rreshti .env* mbetet. Mos kopjo sekretet në kod, raport, pamje ose Issue. Rinis serverin pas çdo ndryshimi të variablave.

-- Pronari fiktiv i ID 1: nuk është llogari reale dhe nuk përdoret për hyrje.

ON CONFLICT (github_id) DO NOTHING;
UPDATE udhetimet SET shofer_id = 'DEMO-SHOFER-2'
WHERE id = '1' AND shofer_id IS NULL;
SELECT id, ora, shofer_id FROM udhetimet ORDER BY id;

A · identiteti dhe sesioni

Skedari: src/lib/auth.ts

Krijo këtë skedar. GitHub verifikon llogarinë; ID-ja e sesionit vjen nga biblioteka, jo nga formulari.

import "server-only";
import type { DefaultSession, NextAuthOptions } from "next-auth";
import GitHubProvider from "next-auth/providers/github";

// GitHub verifikon identitetin. Rolin e lexojmë veçmas nga Neon.
export const authOptions: NextAuthOptions = {
  secret: process.env.NEXTAUTH_SECRET,
  providers: [GitHubProvider({
    clientId: process.env.GITHUB_ID ?? "",
    clientSecret: process.env.GITHUB_SECRET ?? "",
  })],
  session: { strategy: "jwt", maxAge: 2 * 60 * 60 },
  callbacks: {
    async session({ session, token }) {
      if (session.user && token.sub) session.user.id = token.sub;
      return session;
    },
  },
};

declare module "next-auth" {
  interface Session {
    user: { id: string } & DefaultSession["user"];
  }
}

D · kontrolli në server

Skedari: src/lib/lejet.ts

Krijo helper-in. profiliIm lexon sesionin dhe Neon. ndryshoOren kontrollon rolin, fushat dhe pronarin.

import "server-only";
import { getServerSession } from "next-auth";
import { authOptions } from "./auth";
import { getSql } from "./db";

type Profil = { id: string; emri: string; roli: "udhetar" | "shofer" };

export async function profiliIm(): Promise<Profil | null> {
  const session = await getServerSession(authOptions);
  const id = session?.user?.id;
  if (!id || !/^\d+$/.test(id)) return null;
  const sql = getSql();
  // Çdo hyrje e re fillon si udhëtar. Formulari nuk mund të zgjedhë rol.
  await sql`INSERT INTO profilet (github_id, emri) VALUES (${id}, ${session.user.name ?? "Student"})
    ON CONFLICT (github_id) DO NOTHING`;
  const rows = await sql`SELECT github_id AS id, emri, roli FROM profilet WHERE github_id = ${id}`;
  return rows[0] as Profil;
}

export async function ndryshoOren(id: string, ora: string) {
  const p = await profiliIm();
  if (!p) return "hyr";
  if (p.roli !== "shofer") return "ndaluar";
  if (!/^[123]$/.test(id) || !/^([01][0-9]|2[0-3]):[0-5][0-9]$/.test(ora)) return "fushe";
  const sql = getSql();
  // Pronari vjen nga sesioni; jo nga një fushë e formularit.
  const rows = await sql`UPDATE udhetimet SET ora = ${ora}
    WHERE id = ${id} AND shofer_id = ${p.id}
      AND EXISTS (SELECT 1 FROM profilet WHERE github_id = ${p.id} AND roli = 'shofer')
    RETURNING id`;
  return rows.length === 1 ? "ruajtur" : "ndaluar";
}

E · veprimi i ruajtjes

Skedari: src/app/panel/actions.ts

Krijo skedarin. use server e ekzekuton veprimin në server. Leja kontrollohet brenda funksionit, jo vetëm kur faqja hapet.

"use server";
import { redirect } from "next/navigation";
import { revalidatePath } from "next/cache";
import { ndryshoOren } from "@/lib/lejet";

export async function ruajOren(formData: FormData) {
  let mesazh: string;
  try {
    mesazh = await ndryshoOren(String(formData.get("id") ?? ""), String(formData.get("ora") ?? ""));
  } catch {
    mesazh = "databaza";
  }
  if (mesazh === "ruajtur") {
    revalidatePath("/");
    revalidatePath("/udhetimi/2");
  }
  // redirect qëndron jashtë try/catch: Next.js e përdor si kontroll rrjedhe.
  redirect("/panel?m=" + mesazh);
}

4. Hyr dhe cakto pronarin · 45–55 min

  1. Nis npm run dev dhe hap http://localhost:3000/panel, ose Hyr / Paneli im nga lista.
  2. Kliko Hyr me GitHub. Në faqen GitHub prano hyrjen në OAuth App tënd. Pas kthimit duhet të shfaqet emri dhe roli udhetar.
  3. Kopjo numrin pas ID ime GitHub në panel. Në dy komandat e mëposhtme zëvendëso SHENO_ID_TENDE me këtë numër. Mbaji thonjëzat.
  4. Ekzekuto në Neon SQL Editor dhe rifresko panelin. Duhet të shfaqet roli shofer dhe formulari për ID 2.
UPDATE profilet SET roli = 'shofer' WHERE github_id = 'SHENO_ID_TENDE';
UPDATE udhetimet SET shofer_id = 'SHENO_ID_TENDE' WHERE id = '2';
SELECT id, ora, shofer_id FROM udhetimet ORDER BY id;

Pse nga SQL Editor? Në laborator ti je administratori i databazës tënde fiktive. Në aplikacionin real përdoruesi nuk zgjedh vetë rol ose pronar. Nuk ndryshojmë rolin nga një input, URL ose buton në shfletues.

5. Provo, plotëso raportin dhe bëj Push · 55–70 min

Prova 1 · sesioni

  1. Pa hyrë, hap /panel: duhet të kërkojë Hyr me GitHub.
  2. Hyr dhe rifresko. Emri dhe roli mbeten.
  3. Hap panelin në dy skeda të të njëjtit shfletues. Dil në njërën; rifresko tjetrën. Duhet të kërkojë hyrje përsëri.

Prova 2 · veprimi i lejuar

  1. Hyr si shofer i ID 2, vendos 08:25 dhe kliko Ruaj orën.
  2. Paneli tregon sukses. Lista, detajet e ID 2 dhe SQL Editor tregojnë 08:25.
  3. Rikthe 08:15. Shkruaj në java-05.md çfarë pe realisht.

Prova 3 · nuk mjafton ta ndryshosh shfletuesin

  1. Si shofer, në panel: klikim i djathtë mbi Ruaj → Inspect; hapet DevTools (Developer Tools – mjetet e zhvilluesit).
  2. Te Elements gjej <input type="hidden" name="id" value="2">. Dyklik mbi vlerën 2 → shkruaj 1. Mbyll DevTools, kliko Ruaj.
  3. Duhet të shohësh Nuk ke leje për këtë udhëtim. Në SQL Editor verifiko që ora e ID 1 mbeti 08:00.
  4. Për provën e rolit, hape sërish formularin për ID 2. Pa e rifreskuar panelin, në SQL Editor ekzekuto komandën më poshtë. Kliko Ruaj në formularin e vjetër: duhet të refuzohet.
UPDATE profilet SET roli = 'udhetar' WHERE github_id = 'SHENO_ID_TENDE';
  1. Rikthe rolin shofer nga komanda e hapit 4. Hap panelin në dy skeda. Dil në të parën dhe provo Ruaj nga formulari i vjetër i të dytës: kërkohet hyrje.
  2. Shkruaj mesazhet dhe verifikimin e databazës në raport. Mos shkruaj “kaloi” pa provuar. Rikthe rolin shofer dhe orën 08:15 për demonstrimin.

Ndryshimet në DevTools vlejnë vetëm për provën. Serveri nuk i beson ID-së së formularit për pronësinë. Nëse ruajtja pa leje punon, ndalo dhe kontrollo helper-in D me profesorin.

Dorëzo punën · Java 5

Deri në 3 pikë cilësie sipas rubrikës së lëndës. Shpjego një ruajtje dhe një refuzim para se të largohesh.

Nëse hyrja nuk punon
  • Callback mismatch: krahaso adresën dhe portin në GitHub me NEXTAUTH_URL dhe terminalin.
  • Client ID/secret: duhet të jenë të të njëjtit OAuth App. Pas ndryshimit rinis npm run dev.
  • Relation profilet does not exist: ekzekuto schema-java05.sql në të njëjtën degë/databazë si DATABASE_URL.
  • Nuk shfaqet formulari: hyr një herë që të krijohet profili, kontrollo ID-në, rolin dhe pronarin në SQL Editor; rifresko.
  • Nuk ka tabelën udhetimet: rikthe SQL-në e Javës 4 para SQL-së së Javës 5.
Publikimi në Vercel pas provës lokale

Për 90 minutat, prova lokale është e detyrueshme; publikimi është zgjerim. Krijo OAuth App të dytë për adresën e qëndrueshme të projektit në Vercel. Homepage është https://PROJEKTI-YT.vercel.app; callback shton /api/auth/callback/github. Një OAuth App GitHub ka një callback URL: mbaji lokale dhe prodhim veçmas.

Në Vercel vendos GITHUB_ID, GITHUB_SECRET të aplikacionit të prodhimit, NEXTAUTH_SECRET të veçantë dhe NEXTAUTH_URL me adresën HTTPS. DATABASE_URL mbetet. Redeploy pas ndryshimit. Mos përdor adresë Preview të rastësishme si callback.
