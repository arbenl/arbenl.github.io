2. Lidh Neon me Vercel · 10–25 min

Ku: Vercel Dashboard, në projektin tënd RideShare. Neon është shërbim PostgreSQL i integruar përmes Vercel Marketplace. Këtë javë përdorim Neon; Supabase mbetet alternativë, pa instalim shtesë.

  1. Nëse projekti nuk është ende në Vercel: Add New → Project → importo repository-n tënd. Root Directory: aplikacioni nëse kodi është aty. Nëse kodi është pranë README, lëre rrënjën. Publiko versionin ekzistues.
  2. Hap projektin → Storage → Create Database (ose Marketplace) → kërko Neon.
  3. Zgjidh planin Free / $0, emrin rideshare-java4 dhe një rajon afër vendit ku ekzekutohet aplikacioni.
  4. Kliko Connect Project për projektin tënd RideShare. Për orën përdor të njëjtën degë të databazës; mos aktivizo krijimin e degëve të reja për çdo deployment. Kontrollo që variablat të lidhen me Production dhe Development; Preview vetëm nëse të nevojitet.
  5. Te Settings → Environment Variables verifiko se ekziston DATABASE_URL. Neon e shton përmes integrimit. Nëse ka prefiks tjetër, përdor Connection string të Neon për të shtuar variablën me emrin e saktë DATABASE_URL.
  6. Storage → zgjidh Neon → Open in Neon Console. Mbaje hapur; do të përdorësh SQL Editor.

Nëse integrimi ngec: krijo databazën te Neon Console, zgjidh Connect dhe kopjo lidhjen PostgreSQL te DATABASE_URL në Vercel dhe lokalisht. Kjo është e njëjta databazë Neon, pa ndryshuar kodin. Mos zgjidh plan me pagesë për këtë ushtrim.

Kontrollo: shikon databazën tënde dhe SQL Editor. Mos ia dërgo askujt Connection string; përmban kredenciale.

3. Krijo tabelën dhe tri rreshta · 25–35 min

Skedari: schema.sql

Ruaje si schema.sql brenda aplikacionit, pranë package.json. Kopjo kodin në Neon Console → SQL Editor, zgjidh degën/databazën e lidhur me aplikacionin dhe kliko Run. Duhet të shohësh tri rreshta. Ekzekutimi i përsëritur nuk shton kopje.

-- Skedari: schema.sql (brenda aplikacionit, pranë package.json)
-- Të dhëna fiktive për laboratorin; ekzekutohet në Neon SQL Editor.
CREATE TABLE IF NOT EXISTS udhetimet (
  id TEXT PRIMARY KEY,
  nisja TEXT NOT NULL,
  destinacioni TEXT NOT NULL,
  ora TEXT NOT NULL CHECK (ora ~ '^([01][0-9]|2[0-3]):[0-5][0-9]$'),
  vendtakimi TEXT NOT NULL,
  vende INTEGER NOT NULL CHECK (vende >= 0)
);

4. Lidh kodin me Neon · 35–55 min

Në terminalin ku punon aplikacioni ndalo serverin me Ctrl+C. Instalo paketat:

npm install @neondatabase/serverless server-only

Krijo .env.local pranë package.json, brenda aplikacioni/ nëse kodi është aty. Në Neon Console → Connect kopjo Connection string të degës/databazës ku krijove tabelën. Përdor lidhjen e plotë PostgreSQL me parametrat e saj; mos kopjo shembullin si kredencial real.

DATABASE_URL="NGJIT_KETU_LIDHJEN_TENDE_POSTGRESQL"

Alternativë nëse përdor tashmë Vercel CLI (Command Line Interface – ndërfaqe komandash): vercel env pull .env.local nga projekti i lidhur.

Sekreti mbetet privat: mos përdor prefiksin NEXT_PUBLIC_ për DATABASE_URL. Te .gitignore, pranë package.json, sigurohu që ka një rresht .env*. Mos fotografo kredencialet. Nëse GitHub Desktop shfaq .env.local si ndryshim, ndalo dhe kërko ndihmë para Commit.

Kopjo me radhë pesë skedarët A → B → C → D → E më poshtë. Titulli i secilit tregon ku ngjitet kodi. Mos nis serverin pas çdo skedari: në fund të E nis npm run dev, hap adresën e terminalit dhe provo.

Skedarët KartaUdhetimi.tsx, globals.css dhe not-found.tsx nga Java 3 mbeten. Një import vetëm i tipit import type nuk e bart lidhjen private te shfletuesi.

A. Lidhja private me Neon

Skedari: src/lib/db.ts

Krijo këtë skedar. server-only ndalon përdorimin aksidental nga kodi i shfletuesit. DATABASE_URL lexohet vetëm në server.

import "server-only";
import { neon } from "@neondatabase/serverless";

export function getSql() {
  const url = process.env.DATABASE_URL;
  if (!url) throw new Error("Databaza nuk është konfiguruar.");
  return neon(url);
}

B. Zëvendëso të dhënat fikse me SQL

Skedari: src/lib/udhetimet.ts

Zëvendëso gjithë përmbajtjen. Ruajmë të njëjtin tip Udhetim dhe të njëjtin emër gjejUdhetimin. Tani funksionet janë async: rezultati vjen nga databaza.

import "server-only";
import { getSql } from "./db";

export type Udhetim = {
  id: string;
  nisja: string;
  destinacioni: string;
  ora: string;
  vendtakimi: string;
  vende: number;
};

export async function lexoUdhetimet(): Promise<Udhetim[]> {
  const sql = getSql();
  const rows = await sql`
    SELECT id, nisja, destinacioni, ora, vendtakimi, vende
    FROM udhetimet ORDER BY id
  `;
  return rows as Udhetim[];
}

export async function gjejUdhetimin(id: string): Promise<Udhetim | undefined> {
  const sql = getSql();
  const rows = await sql`
    SELECT id, nisja, destinacioni, ora, vendtakimi, vende
    FROM udhetimet WHERE id = ${id}
  `;
  return rows[0] as Udhetim | undefined;
}

C. Lista pret përgjigjen e databazës

Skedari: src/app/page.tsx

Zëvendëso faqen kryesore. Mbaj komponentin KartaUdhetimi dhe globals.css të Javës 3. dynamic kërkon lexim të ri kur hapet ose rifreskohet faqja.

import { KartaUdhetimi } from "@/components/KartaUdhetimi";
import { lexoUdhetimet, type Udhetim } from "@/lib/udhetimet";

// Lexo bazën përsëri në çdo kërkesë për këtë faqe.
export const dynamic = "force-dynamic";

export default async function Home() {
  let udhetimet: Udhetim[];
  try {
    udhetimet = await lexoUdhetimet();
  } catch {
    return (
      <main>
        <h1>RideShare</h1>
        <p role="alert">Nuk u lidhëm me databazën. Provo përsëri.</p>
        <a className="action" href="/">Provo përsëri</a>
      </main>
    );
  }

  return (
    <main>
      <h1>RideShare · Udhëtimet për AAB</h1>
      <p>Burimi: Neon · të dhëna fiktive për ushtrime</p>
      {udhetimet.length === 0 ? (
        <p>Nuk ka udhëtime për momentin.</p>
      ) : (
        <div className="trip-list">
          {udhetimet.map((udhetim) => (
            <KartaUdhetimi key={udhetim.id} udhetim={udhetim} />
          ))}
        </div>
      )}
    </main>
  );
}

D. Edhe detajet lexojnë të njëjtën databazë

Skedari: src/app/udhetimi/[id]/page.tsx

Zëvendëso skedarin ekzistues. Tani përdor await gjejUdhetimin(id). notFound mbetet jashtë try/catch: mungesa e udhëtimit dhe gabimi i lidhjes janë raste të ndryshme.

import Link from "next/link";
import { notFound } from "next/navigation";
import { gjejUdhetimin } from "@/lib/udhetimet";

export const dynamic = "force-dynamic";

export default async function Detajet({
  params,
}: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  let udhetim;
  try {
    udhetim = await gjejUdhetimin(id);
  } catch {
    return (
      <main>
        <h1>RideShare</h1>
        <p role="alert">Nuk u lidhëm me databazën. Provo përsëri.</p>
        <Link href="/">← Kthehu te lista</Link>
      </main>
    );
  }
  if (!udhetim) notFound();

  return (
    <main>
      <Link href="/">← Kthehu te lista</Link>
      <h1>{udhetim.nisja} – {udhetim.destinacioni}</h1>
      <p>Ora: {udhetim.ora}</p>
      <p>Vendtakimi: {udhetim.vendtakimi}</p>
      <p>Vende të lira: {udhetim.vende}</p>
      {udhetim.vende > 0 ? (
        <Link className="action" href={`/udhetimi/${id}/kerkesa`}>
          Kërko vend
        </Link>
      ) : <button className="action" disabled>Nuk ka vende të lira</button>}
    </main>
  );
}

E. Simulimi ruan lidhjen me udhëtimin

Skedari: src/app/udhetimi/[id]/kerkesa/page.tsx

import Link from "next/link";
import { notFound } from "next/navigation";

  params,

  try {

5. Provo dhe ruaje · 55–70 min

Plotëso rezultatet reale te java-04.md. Puno me një koleg: njëri vepron, tjetri parashikon dhe lexon rezultatin. Ndërroni rolet në minutat 35 dhe 55. Çdo student punon në databazën dhe repository-n e vet dhe dorëzon raportin e vet. Në Chrome/Edge: Inspect → ikona telefon/tablet → 375 px.

Prova 1 · Ndryshimi ruhet në databazë

Në Neon SQL Editor ekzekuto:

UPDATE udhetimet SET ora = '08:25' WHERE id = '2';

Rifresko listën. Karta 2 duhet të tregojë 08:25. Hap dhe rifresko detajet e ID 2: edhe aty 08:25. Nuk ndryshove kodin. Në SQL Editor ktheje orën:

UPDATE udhetimet SET ora = '08:15' WHERE id = '2';

Rifresko të dyja faqet. ID 3 ende ka zero vende; ID 99 ende shfaq “Udhëtimi nuk u gjet”.

Prova 2 · Lista bosh nuk është gabim lidhjeje

Te src/lib/udhetimet.ts, vetëm brenda lexoUdhetimet, ndrysho përkohësisht FROM udhetimet ORDER BY id në FROM udhetimet WHERE false ORDER BY id. Ruaj dhe rifresko: shfaqet “Nuk ka udhëtime për momentin.” Nuk fshive asnjë rresht. Hiqe WHERE false, ruaj dhe rifresko: kthehen tri karta.

Prova 3 · Lidhja mungon dhe pastaj rikthehet

Në .env.local riemërto përkohësisht DATABASE_URL në DATABASE_URL_PA_TEST. Ndalo dhe rinis npm run dev. Rifresko listën: “Nuk u lidhëm me databazën. Provo përsëri.” Rikthe emrin DATABASE_URL, ndalo/rinis serverin dhe provo sërish. Mos publiko pamje të këtij skedari.

Sfidë 3-minutëshe për ata që përfunduan: “Udhëtimi u mbush”

Parashiko çfarë ndodh me butonin Kërko vend nëse ID 1 kalon nga 2 në 0 vende. Në SQL Editor ekzekuto UPDATE udhetimet SET vende = 0 WHERE id = '1';. Rifresko detajet e ID 1. A u çaktivizua butoni pa ndryshuar komponentin? Rikthe me UPDATE udhetimet SET vende = 2 WHERE id = '1';. Kjo është sfidë opsionale, pa kërkesë shtesë në dorëzim.
