## Architecture
A focused lib/colloquium service owns additive room and attempt tables, server question bank and timing/scoring. API routes wrap session auth and validation. Professor UI controls lobby and one-way start; student UI joins via room fragment token removed from address, registers inline if needed, polls state and autosaves. Room token stays in memory/sessionStorage only as needed for refresh (no PII/answer keys), not query URLs or logs; cryptographic token stored hash in DB. Existing sessions and room join tokens give same entry route; expose no questions before Start. Staff-only setup invokes migration helper and checks course semester. Course pages link /colloquium. Teacher control /staff/colloquium.
