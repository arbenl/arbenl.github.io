# Mobile 2026/2027 · Week 7 design

Continue the existing RideShare project and syllabus topic, Kollokviumi I dhe kontrolli i MVP-së, on 29 October 2026. Keep the established week navigation, AAB logo, orange week accent, 45-minute lecture per group, 90-minute lab and weekly submissions. No new laboratory points or change to formal colloquium grading.

The lecture follows passenger Arta and driver Dritoni through an MVP review. Include four prediction votes with explanations on subsequent slides, a transparent simulated demo with fault/recovery controls, infrastructure steps separating GitHub deployment from runtime Vercel/Neon requests, pair diagnosis and a final transfer to a real service business. No claim that a browser demonstration persists reservations or verifies identity.

The lab uses the student's existing local Next.js project. No ready-made solution code, ZIP or full-app AI prompt. A locally generated case from GitHub login supplies fictional departure/time/seat values and a case code. It is a reproducible learning variation, not a secret or proof of authorship. No account data leaves the generator. The core work is to inspect the existing app, record two issues, fix one observable issue and re-test the same journey with a changed input. Retain the simulated request label when no real persistence exists. Never ask students to weaken server authorization or store secrets in reports.

90-minute flow: 0–10 setup and personal case; 10–20 independent prediction/baseline commit; 20–45 diagnosis and one correction; 45–60 three real tests and changed-input probe; 60–70 explain in pairs plus instructor spot-check; 70–90 GitHub submission, bot feedback and correction. Initial prediction and live explanation use no AI. Later help may explain an error or hint, with assistance disclosed. A downloadable Markdown report requires case, prediction, two issues, correction path, baseline/final commit links, three expected/actual results, live change explanation and AI disclosure. Working students can continue during the week. A delayed bot is not a reason to duplicate Issues.

The GitHub checker reads only bounded report/package metadata and a recursive path tree pinned to one commit. It verifies evidence structure, source paths and commit ancestry, not the truth of tests, understanding, AI use or a grade. It never runs untrusted code or calls an LLM. Existing weeks remain unchanged. Valid/invalid/recheck workflow cases will be tested using synthetic staff data only.

Limits: neither screenshot/link protection nor variants can make AI use impossible. Direct demonstration and a small new input change provide the practical comprehension check. Screenshots and reports alone are insufficient proof. Class pairs check all students, instructor spot-checks and follows up on unclear explanations.
